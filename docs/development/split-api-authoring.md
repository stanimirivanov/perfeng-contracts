# Split API authoring

## TL;DR

- Edit Run API fragments under `api/run-management/v1/source`.
- Run `make generate-contracts` to regenerate the bundled published API.
- Preserve canonical semantic identity unless separately reviewed wire work changes it.
- Keep authored source, release inventory and exact bundler inputs reviewable.
- Existing clients consume the unchanged published OpenAPI location.

## Source and generated boundaries

Redocly CLI 2.76.0 (MIT) split the existing JSON API into JSON path/component
fragments. Keeping JSON rather than converting to YAML preserves the existing
syntax and avoids another parser. Redocly's root plus paths/components structure
is unchanged. The bundled `api/run-management/v1/openapi.json` is now generated.
Native and Integration ownership remains unchanged until their own slices.

`contracts/api-sources.json` declares each source root, complete fragment inventory,
output path and canonical semantic SHA-256. Every file and reference must stay
inside that declared tree. Source and output ownership paths must be canonical,
including every ancestor; an alias to another location inside api is rejected.
Symlinks, extra files, remote/encoded refs and missing
pointers fail before bundling. The `redocly.yaml` JSON-compatible configuration
admits no inherited config, rules, preprocessors or decorators. The fixed file
and component-name collision errors are mandatory.

## Generation and network isolation

`make generate-contracts` generates Effect schemas and the declared API bundles.
`make api-source-check` compares regenerated bytes and semantic identities.
Generation invokes the exact installed CLI with telemetry disabled in a fresh
network namespace. Developer hosts use unprivileged user/network namespaces.
Hosted Ubuntu uses privilege only to create the network namespace and drops to
the original UID/GID before Node starts. No host networking or global setting
changes. Linux util-linux namespace support is an explicit tooling prerequisite;
unavailable support fails rather than falling back to networked bundling.

The CLI supports Node 24.18.0. It is development-only; consumers receive bundled
language-neutral API bytes. Dependency license/audit and frozen-lock verification
run with ordinary repository acceptance gates.

## Compatibility, review and release

The initial round trip has zero semantic receipt differences. Bundler key ordering
changes serialized bytes and requires a new reviewed snapshot hash downstream;
no path, component root, reference target, enum or field meaning changes.
The canonical identity gate requires an explicit ledger edit for an intended
change. Existing positive/negative and HTTP fixtures remain authoritative.

`contracts/api-release-files.json` declares exactly what the existing candidate
archive includes from `api`. The new source fragments are deliberately included
for reproducibility. No archive publication is performed by the local checks.
Other release content remains selected by the existing workflow. Adding an API
file requires updating this reviewable inventory.

Real temporary Git branches exercise disjoint path edits and a shared component
edit. They merge in both orders and produce identical validated bundles. This
reduces source conflicts; bundled JSON can still need regeneration after rebasing.
Never hand-resolve a generated wire change by dropping conformance evidence.

## Generated Integration fragments

Integration path metadata is grouped into lifecycle and analysis modules. The
Effect definitions under contracts/source remain its sole authored schema source.
`pnpm contracts:generate` and `pnpm contracts:check` now generate/check those
fragments and all declared API bundles using the existing locked Python tooling.
The source registry marks this family with `effect-components`; do not edit its
source fragments manually.

Qualification exposed a Redocly split defect for component-owned nested $defs:
the emitted Error fragment retained a document-root pointer that was invalid in
its new local file. Correcting local pointers then caused Redocly bundle to hoist
nested definitions into new components, changing 152 canonical API pointers.
That representation change was rejected instead of changing expected identity.

Integration therefore uses Redocly-style JSON root/path/component layout with a
bounded custom emitter/assembler, rather than claiming the standard Redocly bundle
round trip supports it. The emitter relocates each reference into its declared
file context. The assembler restores the owning component-root pointer without
hoisting definitions. Every reference resolves locally, and the reconstructed
published object and bytes retain the prior canonical identity. The renderer is
limited to the admitted static component graph; identity-changing schema keywords
and dynamic reference mechanisms require separate admission.

Regression tests preserve the formerly failing external-component pointer case,
exact nested-definition reconstruction, generated fragment drift and unknown-file
refusal. The same release inventory includes these generated fragments. Native
and Run consumers still receive their normal bundled artifacts. No provider
snapshot is selected by generation or this source move.
